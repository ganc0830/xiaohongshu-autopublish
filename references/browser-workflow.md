# 已验证的浏览器流程与故障处理

以下界面名称来自 2026-10-10 实际验证，不保证未来不变。优先读取当前页面，布局变化时更新定位，不盲点坐标。

## 独立会话

复用已授权 CDP 会话最省事。需要新建时，由助手查找本机 Edge 可执行文件，启动独立用户资料目录，使用 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=<空闲端口> --user-data-dir=<任务缓存中的专用目录> --no-first-run --no-default-browser-check`。Windows 后台启动遵从工具要求使用隐藏窗口；用户需要扫码的交互窗口可以显示。

不要附加日常浏览器资料目录，不复制其 Cookie。请用户扫描新窗口二维码并确认账号昵称，界面可提供 ID 时核对。CDP 不能监听所有网卡。连接工具结束后仅断开 CDP 连接，保留用户已登录的浏览器进程。

独立窗口可使用 `--no-proxy-server`，前提是网络排查支持这个选择。不要为了访问网页擅自关闭全机代理。用户已要求临时调整系统代理时，记录原状态并在结束后恢复。

## 上传与内容设置

- 管理页：`https://creator.xiaohongshu.com/new/note-manager`。
- 图文入口：`https://creator.xiaohongshu.com/publish/publish?from=homepage&target=image&openFilePicker=true`。
- 文件：首个 `input[type=file]`，一次按数组顺序 `setInputFiles`。
- 标题提示：`填写标题会有更多赞哦`；填写后 End、Space、Backspace 可触发已观察到的页面更新问题，再读回值。
- 正文：`[contenteditable=true][role=textbox]`。检查规范化后的正文，保留段落和话题。
- 如有“我知道了”引导，先关闭。
- “内容设置” → “添加内容类型声明” → “笔记含AI合成内容”。若已设置，避免重复切换。
- “展开所有图片”后，用精确名称“编辑”的按钮数量确认上传数量。检查顺序和封面仍需看页面截图。
- 图片区域和设置区域分别截图；原创开关保持关闭，公开范围实际读到“公开可见”。如果用户要私密，执行其要求，不能为了脚本便利改成公开。

今天成功上传过 3、6、9 和 13 张的笔记。张数依内容而定，不能将“九宫格”机械解释为每篇只能九张。平台限制应读取当前界面。

## 发布按钮的关闭 Shadow DOM

实测宿主为 `xhs-publish-btn`，属性 `submit-disabled="false"` 表示可提交，内部按钮可能无法通过普通 Playwright 角色选择器定位。

先尝试当前可访问的精确“发布”按钮。无法定位时，保存包含按钮的最新截图，打开图片确认真正按钮中心点，记录宿主 bounding box 与视口。提交时核对这两个值及文案、张数、可见范围和 AI 声明，再在宿主内点击记录点。宿主区域可能还有其他操作，不能直接把宿主中心当发布按钮。

本技能不携带今天的固定坐标。出现按钮遮挡、宿主属性缺失、大小变化或质检过期时，回到准备阶段。

## 成功与审核是两个阶段

等待 URL 包含 `/publish/success` 且页面包含“发布成功”，记录提交成功。随后进入笔记管理，在“已发布”栏目精确查找标题，保存该栏目截图并记录行内日期和状态。实测活动栏目类名为 `tab-item--active`，切换请求路径为 `/api/galaxy/v2/creator/note/user/posted`；脚本等待该请求和选中状态，避免读到前一个栏目残留的行。此路径只用于等待 UI 更新，不直接调用接口发布。接口或类名变化时改用实际界面复核。

如只在“审核中”找到，报告审核中；如在“未通过”找到，记录原因。若多条同名，需进一步核对日期、封面或笔记详情后再归因。列表分页、懒加载、审核延迟都可能导致暂时找不到，不重发。

断网或点击超时尤其要先查管理页。成功页消失并不意味着提交失败，错误提示也可能出现在服务器已接收之后。本地状态在点击前记录尝试，以阻止自动重试。

## 隐私与 GitHub

技能仓库只存规则、脚本和虚构结构示例。浏览器资料、账号配置、真实清单、日志、截图、Cookie、令牌和发布结果留在本地。使用现有 GitHub 认证上传技能时也不得输出凭据。公开技能不代表公开用户的运营账号。
